docs
Architecture and decisions →
  • Stateless API, separate workers. Posting a run writes a record and puts a job on a queue. A worker fleet runs the agents and writes every event to the database, so any API replica can serve the live stream and it survives restarts.
  • Sandboxed builds for AI-written code. Agent code is compiled in a separate builder with no network, no credentials, a read-only filesystem, a non-root user and hard resource limits. On AWS each build is its own Fargate task in isolated subnets with no internet route.
  • Local stack that mirrors AWS. Every AWS service has a local stand-in behind the same interface (SQLite and files for DynamoDB and S3, Redis for SQS, a --network none container for the Fargate task). CI runs the end-to-end test against both, including the real AWS code paths on a moto server, with no AWS account.
  • Written design decisions. ADRs cover Fargate over Lambda, SQS between API and workers, single-table DynamoDB over RDS, and one CloudFront origin for the app, API and games.
